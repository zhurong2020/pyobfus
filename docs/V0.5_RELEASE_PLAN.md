### Original design notes (probe-derived)

An empirical probe (v05 passes → Core mangle+string-encode → exec) proved the
fusion is **not** "run v05 then Core." Findings:

- ✅ opacity L3-encrypted functions survive Core mangling and run correctly.
- ✅ vault survives when run **before** Core string-encoding (literals → bytes;
  Core's StringEncoder skips bytes — `string_encoder.py:123`).
- ✅ emitted `from pyobfus_pro.runtime import …` survive — the SymbolAnalyzer
  drops imported names from the obfuscatable set (`analyzer.py:331`).
- 💥 **`@seal_code` breaks**: seal hashes the function bytecode at v05-time, but
  Core's mangler then renames locals/name → code object changes → runtime
  `IntegrityError`. Seal must run **after** mangling.
- ⚠️ opacity's `@opacity("encrypted")` string arg would be eaten by Core
  string-encoding if opacity ran after it; and opacity v1 raises on class
  methods (real code has them).

**Correct ordering (the deferred "Core parameterization")** — interleave by
splitting Core's pipeline at the mangle / string-encode boundary, with a
tree→source→v05→tree round-trip:

1. Core: **name mangling only**
2. **vault** (literals still literal; mangling doesn't touch string contents)
3. **opacity** (encrypt the *final, mangled* bytecode; decorator arg still literal)
4. **seal** (hash the *final, mangled* code object — or ciphertext for L3)
5. Core: **string-encoding / numeric / dead-code / CFF / …**
6. **scrub** (independent excepthook)

Plus: register `--opacity-config` / `--default-layer` / `--fingerprint` /
`--bind-device` / `--expire-hard` / `--period` / `--scrub-traceback` /
`--seal-code` flags + `ObfuscationConfig` fields; address opacity's
class-method v1 limit; add end-to-end combine tests across 3.9–3.14.
