## 1. 需求来源与决策记录

本次维护者会话的需求逐步收敛为：

1. 探讨 pyobfus 能否扩展为视频加密，使原创正常播放，而搬运后无法播放或出现异常。
2. 明确目标是自己制作、公开上传到 YouTube 或 B 站的视频，不以自有播放器、付费课程或离线设备授权为当前场景。
3. 要求调研代码保护竞品、专业视频保护产品及国际成熟实践。
4. 接受「独立的视频原创保护辅助工具」作为未来方向，并要求记录本次调研，供团队后续溯源。

据此决定：把独立工具列为后续待验证候选，保留现有 Python 兼容性、调试和交付工作顺序。不会将「公开视频搬运后自动播坏」列为产品承诺，也不直接扩入 Core。当前仅有维护者的需求信号，没有外部客户访谈、付费意愿或市场规模证据。

本次变更只涉及研究与规划文档，没有视频原型、媒体样本测试或第三方服务调用结果。

## 2. 结论与技术边界

| 场景 | 可行目标 | 不能据此承诺的能力 |
|---|---|---|
| 自有应用／网站控制播放器与授权 | 加密文件分发、授权后播放；可配合 DRM、账号与设备策略 | 在所有系统阻止录屏，或防止外部摄像机拍屏 |
| 普通创作者公开上传 YouTube／B 站 | 正常投稿；利用水印、内容匹配与平台版权流程发现和处置搬运 | 上传前自定义加密后，仍能直接由平台正常播放且让所有搬运副本失效 |
| 已重新录制、转码的副本 | 尝试识别作品、提取仍然保留的水印、收集人工审核材料 | 原文件的密钥策略仍能控制新副本 |

技术推导：平台必须能解码内容才能处理与播放。即使其自身采用加密传输或 DRM，也不意味着普通投稿者获得了自定义授权控制。公开视频产生可见画面、可听声音后，原文件加密无法普遍控制重新拍摄或编码的新文件。未发现普通投稿流程提供创作者自定义解密许可接口；这不是对平台内部所有商业合作能力的断言。

不能将「录屏黑屏」泛化到所有终端。Apple 的 FairPlay 相关文档描述了指定系统录屏路径中的视频遮黑，同时提示音频需要另行处理；外部拍屏仍不在该保护范围内。[Apple QA1970](https://developer.apple.com/library/archive/qa/qa1970/)

## 4. 国际成熟实践及平台差异

这里的「最佳实践」是结合平台官方能力与厂商资料形成的工程建议，不是单一国际标准或经本项目实测的排名。

### 4.1 公开视频：来源材料、识别、审核、平台处置

- 保留原始素材、剪辑工程、配音稿、导出母版和各平台发布记录；作为来源证据辅助材料，不把单一时间戳或哈希当作所有权的充分证明。
- 在画面、口播等内容中适度保留频道身份。可见水印主要帮助识别和威慑，仍可能被裁剪、覆盖或重绘。
- 优先使用平台内容匹配工具；发现相似不自动等于侵权，需要人工审核授权与适用例外。
- 搬运损失明确后再评估隐形水印和跨平台监测，衡量误报、漏报、处理时间、成本与可操作性。

YouTube 的 Copyright Match Tool 面向复制／潜在复制发现与后续审核；Content ID 可按版权方策略屏蔽、获利或跟踪，但有资格与专有权要求，并非普通账号自动获得。移除申请流程还提供阻止符合条件副本再次上传的选项。平台屏蔽最接近「原创可看，搬运不可看」，但执行方是平台。[版权工具说明](https://support.google.com/youtube/answer/9245819?hl=en)、[Content ID 资格](https://support.google.com/youtube/answer/1311402?hl=en)、[匹配工具操作与限制](https://support.google.com/youtube/answer/7648743?hl=en)

B 站官方创作中心于 2024-05-08 公告「原创保护」：通过认证后可获得站内作品保护，平台识别疑似侵权，UP 主确认后处置。该历史公告不能证明所有账号在 2026-10-23 均有入口，也不能据此承诺站外自动保护；后续需在实际账号创作中心核实权益与申请条件。[B站官方公告](https://www.bilibili.com/opus/929058132596883576)

### 4.2 区分指纹、水印、来源凭证与加密

| 技术 | 作用 | 边界 |
|---|---|---|
| 文件密码学哈希 | 判断完整字节是否相同、记录母版完整性 | 转码后通常变化；不能替代内容相似度检测或单独证明归属 |
| 音视频内容指纹 | 匹配同一作品或相似片段 | 不要求提前嵌入标记；需要参考库，存在误报／漏报 |
| 隐形水印 | 提取预先嵌入的作品、版本或接收者标记 | 依赖具体算法及处理条件；不能假定任意剪辑后都存活 |
| C2PA／Content Credentials | 提供可验证的来源及处理记录 | 不是播放许可、完整版权确权或防复制机制；元数据可能被移除 |
| DRM／授权加密播放 | 在受支持的播放链路控制解密与许可 | 需要播放器与授权生态配合，不控制任意重新录制的副本 |

尤其注意：公开视频若所有观众看到同一水印版本，只能据此标记作品／发布来源，不能定位是哪位观众下载或录屏。按观看者溯源需要分发不同标记的版本及相应分发系统支持。

C2PA 官方描述可借助水印或指纹等 soft binding 重新关联被移除的凭证；不能据此承诺所有平台保留或恢复凭证。YouTube 对 C2PA 的部分来源披露支持，也不等于提供创作者自定义防复制授权。[C2PA FAQ](https://c2pa.org/faqs/)、[YouTube 来源披露](https://support.google.com/youtube/answer/15447836?hl=en)

### 4.3 受控视频分发：保留为对照场景

自有付费／内部视频服务可组合 DRM、登录授权、令牌、设备策略及取证水印。Widevine／FairPlay 是现有技术生态；标准 HLS AES 加密与完整 DRM 不能等同。阿里云官方也明确私有加密不能阻止录屏、截屏，标准 HLS 密钥存在被窃取的风险。本候选不以自研 DRM 或专用播放器为首期目标。

资料：[Widevine](https://developers.google.com/widevine/drm/overview)、[FairPlay](https://developer.apple.com/streaming/fps/)、[阿里云媒体安全](https://help.aliyun.com/zh/vod/user-guide/media-video-security)、[私有加密限制](https://help.aliyun.com/zh/vod/user-guide/alibaba-cloud-proprietary-cryptography)、[腾讯云按观看者溯源示例](https://cloud.tencent.com/document/product/266/75789)。

## 5. 后续团队候选：独立的视频原创保护辅助工具

目标用户：公开发布原创视频的个人创作者、小型内容团队。待验证问题：母版与发布证据分散、搬运发现慢、疑似片段人工比对与申诉材料整理耗时。

建议探索范围（均待单项确认）：

1. 母版、素材与发布记录管理，记录完整性哈希及可追溯版本关系。
2. 可见水印、平台／版本标记生成；隐形水印先做现有方案评估。
3. 对用户提供或合法获取的疑似搬运样本进行音视频片段比较。
4. 输出原作、疑似副本、对应时间段与来源链接等人工审核材料。
5. 后续有需求再评估平台接口、监测服务和来源凭证集成，不假设有平台私有版权 API。

不承诺公开视频副本自动失效、绝对防录屏或自动确权；不把自动投诉／下架作为首期默认动作。相似度结果需人审，真实平台操作另行确认范围。

### 5.1 与 pyobfus 的边界及版本政策

pyobfus 的 AST 引擎不能处理视频编码数据；现有 `embed_data` 资源保护、设备／到期授权与代码取证水印是应用分发能力，不能直接替代媒体水印或视频 DRM。现有客户端信任边界继续适用。[架构](PROJECT_STRUCTURE.md)、[威胁模型](THREAT_MODEL.md)

倾向独立产品或实验模块，具体仓库、名称、许可证与收费均未决定。按 [版本边界政策](EDITION_BOUNDARY_POLICY.md) 评估：本地检查／验证原语与托管监测、组织协作、分发控制／买家溯源分开讨论；不能因候选立项而收紧现有 Community 能力。用户／买家／问题／需求证据必须在正式立项时复核，目前没有已验证买家或付费需求。

### 5.2 下一轮评估的进入与验收条件

- 明确平台、视频类型、搬运频率、当前处理耗时与可接受成本，获得外部创作者反馈。
- 重新核实平台权益、接口权限与竞品文档；保存精确版本、日期、条款和可复现实验材料。
- 如决定原型，使用自有或明确授权样本，对平台转码、压缩、裁剪、变速、加边框、字幕覆盖、短片段及拍屏分别测试；同时加入无关作品测误报。
- 记录指纹／水印的成功率、误报／漏报、最短可检测片段、画质影响、处理耗时与成本；尚未设阈值，原型前确定。
- 用实际人工审核与材料整理耗时验证价值，再决定自研、集成或停止；本次记录不设置虚构交付日期。
